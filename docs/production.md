# Leela: ежедневное производство и проверка

Активна только Maya. Каждый день резервируются два разных ролика на следующий календарный день по Europe/Minsk. Расписание публикации берётся из двух слотов каждого канала Buffer в America/New_York; время запуска генератора не определяет время публикации.

## Расписание и сохранённые задания

cron-job.org запускает GitHub Actions через workflow_dispatch каждый час с 11:17 до 18:17 по Europe/Minsk (`17 11-18 * * *`). Задание 8631883 включено 12 октября 2026 года; тестовый dispatch 38285576481 прошёл успешно и не создал повторные ролики. Встроенный schedule генератора удалён. Для паузы выключить задание cron-job.org; PRODUCTION_ENABLED не управляет внешним dispatch.

Два ID, фразы, сцены и точные времена публикации сохраняются до генерации в приватном R2: `content-factory/production/v2/ledger.json`. Повторный запуск использует эти задания. Изменение конфигурации не переписывает уже зарезервированные ролики. Старый журнал v1 не возвращается в очередь.

## Лицо и разнообразие

`config/production.json` содержит восемь сцен Maya: кафе, кухня, парк, рабочий стол, диван, балкон, книжный магазин, терраса. Для каждой заданы обстановка, одежда, ракурс и эмоциональная реакция. Сцены выбираются по минимальному числу использований, без соседних повторов и с проходом всего пула перед следующим циклом. Снимок сцены сохраняется в задании; статистика — в `scene_usage` и `last_scene` персонажа.

Приватное фото `content-factory/assets/leela/maya-reference.png` служит образцом личности, а не обязательным фоном или костюмом. Gemini создаёт для каждого нового задания вертикальный кадр 9:16, сохраняя черты лица и меняя сцену. Затем Veo оживляет этот кадр с естественной синхронной репликой «No way!». Обе операции имеют приватные checkpoints: неизвестный результат платного запроса не приводит к повторному POST. Результат сохранения лица проверяется владельцем в Telegram, абсолютное сходство автоматически не подтверждается.

Актёрский фрагмент создаётся отдельно для каждого видео. Формат: полная четырёхсекундная реакция человека → вся игровая запись на скорости 2.5× → двухсекундная остановка последнего игрового кадра. Музыка продолжается между частями, реплика не заменяется отдельной озвучкой. Описание всегда строго `Find Leela on Telegram: @leela_ru_bot`.

`actor_seconds: 4` сохраняется в новых заданиях и передаётся в платный запрос Veo как durationSeconds. Проверяется наличие звука и соответствие длительности; старые задания без этого поля сохраняют прежние 8 секунд. При двух роликах в день ориентир за 30 дней — $12 на Veo Lite плюс около $2 на изображения сцен и небольшой расход на входные данные.

`config/phrases-en.json` хранит пул вопросов и текстовых мыслей. Фразы также выбираются по минимальному числу использований. Alex и Zoe отключены.

## Telegram и Buffer

Каждый готовый ролик сразу отправляется владельцу в Telegram с кнопками одобрения и отклонения. Решение привязывается к владельцу, исходному сообщению и SHA-256 конкретного видео. Первый ответ сохраняется; повторное нажатие не создаёт новый пост.

Cloudflare Worker `leela-video-review` принимает Telegram webhook: проверяет секрет Telegram, владельца, исходное сообщение, receipt и SHA-256. Решение сохраняется сразу в приватном `review-decisions/{job_id}.json` условной записью; первое решение остаётся окончательным. Кнопка обновляется в том же запросе. Cloudflare cron каждую минуту переносит решение в журнал и отправляет одобренный ролик в Buffer с общей R2-блокировкой. Задержку может вызвать работающая генерация или недоступность внешнего API.

GitHub `Telegram video review` остаётся резервным обработчиком: при нашем webhook не вызывает getUpdates, но читает сохранённые решения и продолжает доставку. При чужом webhook останавливается. Платные генерации этот обработчик не запускает. Настройки Telegram и Buffer хранятся в секрете CONFIG Worker; временный объект переноса удаляется после активации. Код и конфигурация: `workers/telegram-review/`. HTTP-запросы Worker используют redirect: manual: Cloudflare не поддерживает redirect: error. Ответы 3xx не считаются успехом, перенаправления с секретами не выполняются.

Одобренное видео отправляется по одному разу в YouTube, TikTok и Instagram через Buffer с `customScheduled` и сохранённым `dueAt`. Полная очередь (лимит 10), занятый слот или неопределённый результат запроса не приводят к слепой повторной отправке. Просроченное одобрение получает статус expired. Отклонение не запускает автоматическую замену.

Основной R2 bucket приватный: фото, исходник, изображения сцен, актёрские фрагменты, ответы API, готовые файлы и журналы. Только одобренный MP4 копируется в отдельный публичный bucket под случайным именем с постоянной ссылкой для Buffer. Ключи и ответы с медиа не выводятся в публичные логи.

## Восстановление

Для явного ответа Google об аудиоошибке **без списания** допускается одна автоматическая замена с новым ID и прежними временем, фразой и сценой. Неизвестные результаты, таймауты и прочие блокировки не повторяются. Второй отказ сохраняется для ручной диагностики. Успех одного ролика не теряется при сбое второго.

Статус доставки unknown означает, что запрос мог дойти до Buffer. Нужно сверить существующий пост и сохранить его ID; новый POST автоматически запрещён. Оставшуюся lock.json разбирают только после проверки, что workflow и платная операция больше не работают.

## Проверки

```sh
python -m unittest discover -s tests -p 'test_*production.py' -v
python -m unittest discover -s tests -p 'test_actor_scenes.py' -v
```

Проверяются две дневные резервации, повторные запуски, часовые пояса и DST, циклы сцен и неизменность снимков, сохранение изображения после сбоя без повторного платного запроса, ограничения очереди и неопределённые отправки. Эти проверки не заменяют просмотр нового ролика и проверку фактической публикации.

## Внешний запуск через cron-job.org

Workflow принимает workflow_dispatch с execute=true. Внешнее задание https://console.cron-job.org/jobs/8631883 создано, проверено и включено. Встроенный cron генератора удалён; ручной workflow_dispatch сохранён.

1. Создать GitHub fine-grained personal access token: resource owner Mirrorby, Only select repositories → content-factory, Repository permissions → Actions: Read and write. Остальные права не добавлять; следить за сроком действия токена.
2. В cron-job.org создать задание Leela daily pair. Часовой пояс Europe/Minsk, расширенное расписание: минута 17, часы 11–18 включительно, все дни. Эквивалент cron: `17 11-18 * * *`.
3. URL: `https://api.github.com/repos/Mirrorby/content-factory/actions/workflows/production.yml/dispatches`.
4. Метод POST; заголовки:

| Заголовок | Значение |
| --- | --- |
| Authorization | Bearer YOUR_FINE_GRAINED_TOKEN |
| Accept | application/vnd.github+json |
| Content-Type | application/json |
| X-GitHub-Api-Version | 2026-03-10 |
| User-Agent | content-factory-cron |

Тело запроса:

```json
{"ref":"main","inputs":{"execute":true}}
```

Токен вводится только в приватном интерфейсе cron-job.org, не в код, описание задания или чат. Он даёт сервису возможность управлять Actions выбранного репозитория. Включить уведомление об ошибке/автоматическом отключении задания. HTTP 2xx подтверждает принятие запуска, но не успех генерации: проверять Actions и доставку пары в Telegram. Повторные запросы используют сохранённые ID дневной пары; concurrency не допускает параллельные генераторы.

Тестировать через Test run и проверять новый workflow_dispatch в GitHub Actions. Schedule из production.yml уже удалён после проверки. Для остановки внешних запусков выключить задание cron-job.org (workflow_dispatch сейчас не зависит от PRODUCTION_ENABLED).
