# Контент-фабрика — первый запуск на GitHub Actions

Версия 0.1: готовый сценарий → три изображения Gemini → MoneyPrinterTurbo →
вертикальный ролик с озвучкой и субтитрами → приватное хранилище Cloudflare R2.

Запускается вручную через **Run workflow**, без Colab и работающего ноутбука.
Автовыбор тем, расписание, публикация в соцсети и Telegram ещё не реализованы.
Текущий этап проверяет генератор в новой среде. Условия использования Actions
по-прежнему применяются; открытость репозитория не меняет назначение сервиса.

## 1. Создать репозиторий

Создай на GitHub публичный репозиторий `content-factory`.
Загрузи **содержимое** этой папки в корень репозитория.
Файл workflow должен оказаться по пути `.github/workflows/generate.yml`.
Не загружай ZIP одним файлом: GitHub не распаковывает его автоматически.

На macOS `.github` скрыта. В Finder нажми **Cmd + Shift + .**, чтобы её увидеть.
Если загружаешь через браузер и скрытая папка не переносится, создай файл
`.github/workflows/generate.yml` через **Add file → Create new file** и вставь
его содержимое из архива. Остальные папки загрузи через **Upload files**.

Исходный MoneyPrinterTurbo автоматически скачивается при запуске с закреплённого
коммита `8e259e9f072c9e08464f040cd658d4eb046a57d0`. Его код не включён в этот архив.

## 2. Подготовить Cloudflare R2

1. Открой Cloudflare Dashboard → R2 Object Storage.
2. Создай Standard bucket, например `content-factory-media`, с обычной
   автоматической локацией (эта версия использует глобальный S3 endpoint).
3. Оставь публичный доступ выключенным. Домен и публичная ссылка не нужны.
4. Создай R2 API token с правами **Object Read & Write** только на этот bucket.
5. Сохрани Account ID, Access Key ID и Secret Access Key.

R2 может предложить подключить платёжный метод для активации.
Файлы хранятся до ручного удаления; автоматической очистки в версии 0.1 нет.

## 3. Добавить пять секретов GitHub

Repository → **Settings → Secrets and variables → Actions → New repository secret**.

| Имя | Значение |
|---|---|
| `GEMINI_API_KEY` | Действующий ключ проекта Gemini с оплатой изображений |
| `R2_ACCOUNT_ID` | ID аккаунта Cloudflare, 32 символа; не URL |
| `R2_ACCESS_KEY_ID` | Access Key ID из R2 |
| `R2_SECRET_ACCESS_KEY` | Secret Access Key из R2 |
| `R2_BUCKET` | Имя bucket, например `content-factory-media` |

Не вставляй ключи в код, README, issues или сообщения. Репозиторий и журналы
Actions публичны. Изображения, полный ответ Gemini и диагностические журналы
сохраняются в приватный R2. Подписанные ссылки не выводятся.

## 4. Создать первый ролик

1. Открой **Actions → Generate pilot video → Run workflow**.
2. Оставь `job_id = pilot-001` и запусти.
3. Дождись завершения. Прогресс виден в шаге **Generate and save to R2**.
4. Скачай через панель R2 файл:
   `content-factory/v1/pilot-001/final.mp4`.

В этой версии используется тестовый текст о выборе пути — около 10 секунд.
Три кадра идут последовательно, каждый максимум 4 секунды. Точной привязки
к отдельным фразам пока нет; последний кадр обрезается по длительности озвучки.

На новый job выполняется не более **трёх запросов генерации изображений**.
Gemini оплачивается из твоего баланса; лимит числа запросов не является
фиксированным денежным бюджетом. Текст готов заранее, музыка выключена,
озвучка использует Edge TTS. Изменить сценарий и промпты можно в `factory/core.py`.

## Повторный запуск и ошибки

- Повтори **тот же job_id**, чтобы продолжить существующее задание.
- Новый job_id означает новый ролик и новые платные генерации.
- Сохранённые картинки скачиваются из R2 и повторно не генерируются.
- Перед платным запросом статус `pending` записывается в R2. Если ответ потерян,
  автоматического повтора нет. Это защищает от двойной оплаты, но иногда требует
  ручной проверки. Пришли сообщение ошибки, не удаляя состояние задания.
- Ответ Gemini сохраняется до обработки изображения. После остановки его можно
  обработать снова без нового запроса.
- После ошибки монтажа изображения остаются, а монтаж и озвучка могут повториться.
- Готовность фиксируется после загрузки видео и субтитров в R2.
- `lock.json` предотвращает одновременную обработку одного job даже из разных
  сред. При обычном завершении он удаляется. После жёсткой остановки он может
  остаться: убедись, что ВСЕ запуски этого job завершены, затем удали **только**
  `lock.json` через R2 и повтори с тем же ID. `state.json` не удаляй.
- Журналы `preflight.log` и `render.log` находятся рядом с материалами в R2.
- В этой версии ошибка HTTP или отсутствие картинки тоже требует проверки:
  автоматические повторные платные запросы намеренно отсутствуют.

GitHub ограничивает workflow здесь 150 минутами; сам монтаж — 120 минутами.
Расписание не включено, fork/PR не запускают генерацию. У workflow только
`contents: read`, без разрешения на запись кода.

## Что проверено

Проверены синтаксис Python/YAML, восстановление кадров, отсутствие повторного
POST при потерянном ответе и порядок сохранения состояния с имитацией API.
Полный запуск на GitHub, реальное подключение к твоему R2, озвучку и монтаж
нужно проверить первым workflow. Секретов и доступа к твоим аккаунтам в архиве нет.

## Дальнейшая работа и перенос

После просмотра первого ролика: автоматические темы и сценарии, очередь,
публикация, затем расписание и отчёты. Не запускай одну очередь одновременно
с двух площадок при переносе.

Ядро не зависит от GitHub API. Команда запуска — `python run.py`; настройки
передаются через переменные окружения. Для Railway понадобится добавить
Dockerfile с теми же зависимостями и настроить запуск; перенос ещё не проверен.
Хранилище R2 и job_id можно сохранить, чтобы использовать прежние кадры.
